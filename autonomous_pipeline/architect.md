# Autonomous Pipeline — Architecture Document (EN + VI)

This document is the complete project map for the Ciel 2.0 Autonomous MLOps Pipeline subsystem.

---

## 1) High-Level Architecture | Kiến trúc tổng thể

The Autonomous Pipeline is a **self-running background daemon** that operates independently from the main Ciel CLI. It simulates a Master giving tasks, lets Ciel execute them, then uses a separate Judge model to audit the quality and build a fine-tuning dataset.

Three actors, three models, one loop:

| Actor | Model | Role |
|---|---|---|
| **Simulated Master** | `deepseek-v4-flash` | Generates realistic, context-aware tasks based on time-of-day schedule and recent history |
| **Ciel (Brain + Worker)** | `gemini-2.5-pro` + `gemini-2.5-flash` | Executes the task end-to-end (routing, tool calls, code gen, response) |
| **The Judge** | `deepseek-v4-pro` | Audits Worker responses for hallucination, conciseness, persona compliance. Produces critique + recommendations |

- **Entry point (production):** `orchestrator.py` — background daemon with time-based scheduling
- **Entry point (testing):** `test_end_to_end.py` — immediate single-cycle test harness
- **Task generation:** `task_generator.py` — calls DeepSeek to generate a task, then runs it through `AgentLoop`
- **Judge audit + dataset:** `data_pipeline.py` — reads `ciel_data/logs/thoughts.log`, audits with DeepSeek Judge, augments fine-tune dataset, sends Telegram alerts
- **State persistence:** `state.json` — tracks log seek cursor, cumulative metrics, scheduling timestamps

## 2) Runtime Flow | Luồng chạy

### Production Pipeline (orchestrator.py — VPS daemon)

```
Daemon Boot → Telegram "ONLINE" notification
  │
  ├── Every 1 Hour:
  │     1. Snapshot thoughts.log file size (pre_task_seek)
  │     2. task_generator.py:
  │        → Load last 3 user prompts from thoughts.log (lookback mechanism)
  │        → Call DeepSeek-v4-flash (Simulated Master) → generate task
  │        → Initialize AgentLoop → Ciel executes task
  │        → Task results logged to ciel_data/logs/thoughts.log
  │     3. Set state.json seek cursor = pre_task_seek
  │     4. data_pipeline.py:
  │        → Read thoughts.log from pre_task_seek (fresh entries only)
  │        → Parse [USER][REQUEST] + [WORKER][*_RESPONSE] pairs
  │        → Send batch to DeepSeek-v4-pro (The Judge)
  │        → Judge returns: evaluations + overall_critique + improvement_recommendation
  │        → Auto-correct WEAK responses, discard BAD, augment GOOD with 2 paraphrases
  │        → Retry up to 3 attempts on JSON parse failure (exponential backoff)
  │        → Append ChatML records to worker_finetune.jsonl
  │        → Log Judge audit to autonomous_pipeline/thoughts.log
  │        → Render Pillow dashboard image
  │        → Send Telegram alert with metrics + critique + recommendation
  │
  └── Daily at 23:00:
        → Full nightly audit of any remaining unprocessed log entries
        → Same Judge + Telegram flow as above
```

### Test Pipeline (test_end_to_end.py — manual trigger)

```
Phase 1: Snapshot log → Generate task → Ciel executes
Phase 2: Read from snapshot → Judge audit → Telegram alert
```

Same logic as production, but runs once immediately and exits.

## 4) state.json Schema | Cấu trúc state

```json
{
  "last_processed_seek": 1225510,     // Byte position in ciel_data/logs/thoughts.log
  "total_processed": 17,              // Lifetime Worker transactions audited
  "total_accepted": 16,               // Lifetime GOOD + corrected WEAK kept
  "total_rejected": 1,                // Lifetime BAD (hallucinated) discarded
  "cumulative_dataset_size": 38,      // Total ChatML pairs in worker_finetune.jsonl
  "last_task_gen_timestamp": 1748..., // Unix timestamp of last task generation (orchestrator only)
  "last_audit_date": "2026-05-26"     // Date of last nightly 23:00 audit (orchestrator only)
}
```

**Critical behavior:** Before each task cycle, the orchestrator snapshots `thoughts.log` file size and resets `last_processed_seek` to that snapshot. This guarantees the Judge reads exactly the entries Ciel just produced — not stale or already-processed content.

**Judge reliability:** Batch size is capped at 4 items (previously 10). Worker responses are truncated to 800 chars in the audit payload to prevent DeepSeek from hitting `max_tokens` and truncating JSON mid-response. On JSON parse failure, the pipeline retries up to 3 attempts with progressive temperature (0.2 → 0.3 → 0.4) and exponential backoff (2s, 4s).

**Worker guardrails:** All Worker prompts (`execute_tool`, `execute_code`, `execute_multi_tool`, `execute_chat`) include explicit anti-hallucination rules ("NEVER fabricate data") and persona enforcement ("Always address the user as Master").

## 5) Two Separate thoughts.log Files | Hai file log riêng biệt

| File | Written by | Contains |
|---|---|---|
| `ciel_data/logs/thoughts.log` | Ciel core (Brain, Worker, Tools, RAG) | Full runtime trace: `[USER]`, `[BRAIN]`, `[WORKER]`, `[TOOL]`, `[RAG]` entries |
| `autonomous_pipeline/thoughts.log` | `data_pipeline.py` + `task_generator.py` | DeepSeek API calls only: `[SIMULATED_MASTER]`, `[JUDGE]` prompts + responses |

The Judge reads FROM `ciel_data/logs/thoughts.log` and writes its audit results TO `autonomous_pipeline/thoughts.log`.

## 6) Judge Evaluation Criteria | Tiêu chí đánh giá của Judge

The Judge (DeepSeek-v4-pro) evaluates each Worker response against 3 criteria:

1. **NO HALLUCINATION**: Response must only contain facts from Raw Tool Results. Invented data → `[BAD]`
2. **CONCISENESS**: Must be extremely direct. No filler or conversational fluff. Too verbose → `[WEAK]`
3. **PERSONA**: Must address user as "Master" — but **code-routed responses are exempt** (Python scripts don't need persona greetings)

### Classification Actions

| Classification | Action |
|---|---|
| `GOOD` | Keep original + generate 2 diverse paraphrases (3 ChatML pairs total) |
| `WEAK` | Rewrite to meet GOOD standard (1 corrected ChatML pair) |
| `BAD` | Discard entirely — hallucinated content never enters training data |

### Structured JSON Response

The Judge returns a single JSON object with:
- `evaluations[]` — per-item classification, reasoning, paraphrases/rewrites
- `overall_critique` — 2-sentence batch performance summary
- `improvement_recommendation` — 1 actionable tip for next training cycle

```

📊 Today's Performance Breakdown:
• Processed: X worker items
• Accepted/Augmented: Y records
• Hallucinated/Discarded: Z records

📈 Finetune Dataset Progress:
• Added today: +N ChatML pairs
• Cumulative Size: M ChatML pairs

⚖️ Judge's MLOps Assessment:
• Critique: [Judge's overall evaluation]
• Recommendation: [Actionable improvement tip]

📝 Recent Tasks & Outcomes Summary:
1. Task: [truncated request]
   ↳ Ciel: [truncated response]
```

Plus a Pillow-rendered dashboard PNG image attachment.

```bash

```

### Dependencies

All dependencies are shared with the main Ciel 2.0 project (`myenv` virtualenv):
- `requests` — DeepSeek API calls
- `Pillow` — Dashboard image rendering
- `python-dotenv` — Environment variable loading
- `sentence-transformers` — RAG embeddings (loaded by Ciel core)

API keys required in `.env`:
- `DEEPSEEK_API_KEY` — For Simulated Master (flash) and Judge (pro)
- `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` — For alerts
- `GEMINI_API_KEY` — For Ciel Brain + Worker
