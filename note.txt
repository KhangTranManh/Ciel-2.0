================================================================================

  STATUS: ✅ DONE (2026-05-11)
  FILE:   skills/external/github_ops.py

  WHAT:
    Give Ciel the ability to manage Git repositories directly. This turns her
    from a "chat advisor" into a "Junior Developer" who can execute version
    control operations on the Master's behalf.

  TOOLS TO BUILD:
    1. git_status()     — Show changed/staged/untracked files.
    2. git_diff()       — Show the actual code changes before committing.
    3. git_commit_and_push(message) — Stage all, commit, and push.

  CRITICAL SAFETY RULES:
    - MUST require explicit "Y/N" user approval before executing push.
    - MUST never commit .env or files listed in .gitignore.
    - MUST show a preview of what will be committed before asking approval.

  WHY THIS WAS CHOSEN:
    The Master's goal is to make Ciel a virtual assistant for work. The biggest
    friction right now is that Ciel can write/fix code but cannot commit it.
    This feature eliminates that friction and makes Ciel a true collaborator.

  RISKS DISCUSSED:
    - Ciel could accidentally overwrite a branch or discard uncommitted changes.
    - Ciel could commit sensitive files (.env, API keys).
    - Solution: strict safety rails + mandatory user confirmation.

  PRIORITY 2: 11:00 PM "Brain Cleanse" (Scheduled Task)
================================================================================

  STATUS: DONE (2026-05-11)
  FILE:   core/scheduler.py (add new task to existing file)

  WHAT:
    A nightly scheduled task that flushes ALL remaining short-term memory
    (memory_bank.json) into the RAG vector database (ChromaDB), then generates
    a "Daily Summary" entry in RAG so Ciel can recall what happened each day.

  HOW:
    1. At 23:00, read all messages from memory_bank.json.
    2. Archive every message into ChromaDB via rag_manager.add_memory().
    3. Use Worker (1 API call) to generate a concise "Daily Summary" of all
       the day's interactions.
    4. Save the summary into RAG as a special "daily_summary" entry.
    5. Clear memory_bank.json to start fresh the next morning.
    6. Optionally notify Master via Telegram: "Brain cleanse complete."

  WHY:
    Prevents context bleed across days. Every morning starts clean and fast.
    The Daily Summary in RAG means the Master can ask "What did we do last
    Tuesday?" and Ciel will find it via semantic search.

  RISKS DISCUSSED:
    - If Master is working late (past 11 PM) on a complex task, the cleanse
      could wipe the active conversation context mid-flow.
    - Solution: Add a "grace period" check — if the last message was within
      the past 30 minutes, skip the cleanse and retry at midnight.

  PRIORITY 3: RAG Re-ranking (Advanced Memory Optimization)
================================================================================

  STATUS: Discussed, DEFERRED until needed.
  FILE:   core/rag_manager.py (modify search_similar)

  WHAT:
    Add a local cross-encoder model (e.g., bge-reranker-base) that runs on the
    RTX 3060 to re-score RAG search results. Currently, search_similar returns
    results based on pure cosine similarity. A re-ranker would use deeper
    semantic understanding to filter out "similar but irrelevant" memories.

  HOW:
    1. search_similar() fetches top 10 results from ChromaDB (instead of 3).
    2. Pass all 10 results + the query through the cross-encoder.
    3. Re-rank by semantic relevance score.
    4. Return only the top 3 highest-scoring results to the Brain.

  WHY IT WAS DEFERRED:
    The current RAG system passed a 45-prompt stress test with 100% accuracy
    on the critical recall test. The noise filters (MIN_QUERY_LENGTH=15,
    MIN_RELEVANCE_SCORE=0.65) plus the 2026-05-21 recall compressor are already
    doing a good job. Adding a
    cross-encoder would:
    - Consume 1-2 GB extra VRAM on the RTX 3060.
    - Add latency to every single user message.
    - Add architectural complexity to a system that is currently healthy.

  WHEN TO REVISIT:
    - When the RAG database grows beyond 10,000+ memories.
    - When the Master notices Ciel recalling irrelevant or confusing context.
    - When upgrading to a GPU with more VRAM (e.g., RTX 4090).

================================================================================

  STATUS: ✅ DONE (2026-05-11)

  WHAT:
    Give Ciel "eyes" on the internet. Instead of relying on static APIs, Ciel

    Jarvis isn't Jarvis if he's stuck in 2024. Web search allows Ciel to bypass
    API limitations and access the entire internet's live knowledge base while
    remaining undetectable by anti-bot systems (Cloudflare, etc.).

  PRIORITY 5: Vision & UI Interaction (The Hands of Ciel)
================================================================================

  STATUS: ✅ DONE
  FILE:   skills/internal/vision_ops.py (NEW)

  WHAT:
    Two-tier autonomous Vision & UI Interaction system. Ciel plans the optimal
    approach: CLI shortcuts for navigation (0 vision tokens), then visual 
    interaction only for UI elements that require seeing the screen.

  HOW:
    TIER 1 — Pre-flight Planner (text-only Gemini, near-zero cost):
      1. Analyze task → determine if CLI/URL shortcut is possible.
      2. For YouTube: open youtube.com/results?search_query=... directly.
      3. For apps: launch via subprocess (e.g. notepad.exe).
      4. If CLI handles 100% of task → return immediately (0 screenshots).
    TIER 2 — Vision Loop (only for remaining UI interaction):
      5. Capture screenshot + draw 10×8 labeled grid overlay (A1-J8).
      6. Send gridded screenshot to Gemini 2.5 Flash Vision.
      7. Execute PyAutoGUI actions (click, type, hotkey, scroll).
      8. Loop until task complete (max 10 steps).
    SAFETY:
      - Loop-break detector: auto-stops after 3 identical actions.
      - Auto Ctrl+A before typing to prevent text appending.
      - pyautogui.FAILSAFE=True (mouse to corner aborts).

  WHY:
    Enables true Jarvis-like interaction: "Ciel, play lofi on YouTube".
    Old approach: 10+ vision steps just to navigate. New: 1 CLI + 1-2 vision steps.
